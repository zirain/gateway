Added a `serviceSettings` field under `EnvoyGateway.spec.rateLimit` to configure connection-level behavior for the global rate limit service cluster, such as `circuitBreaker.maxRequestsPerConnection` and `timeout.http.maxConnectionDuration`. Only settings that apply to the managed gRPC rate limit service are exposed: load balancing (`RoundRobin`, `LeastRequest`, `Random`, with optional slow start), TCP keepalive, circuit breakers, connection and stream timeouts, connection buffer limits, and HTTP/2 settings. These fields are validated at config-load time, so an invalid value is rejected at startup instead of only once a Global rate limit policy is used.
